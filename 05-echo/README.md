# 05-echo ✅

TCP エコーサーバー。クライアントから受け取った行をそのまま送り返す。

---

## 仕様
- ポート `4242` で TCP 接続を待ち受ける
- 接続してきたクライアントが 1 行送ったら、その行をそのまま送り返す
- クライアントが切断するまで繰り返す
- **複数のクライアントが同時に接続できる**こと
- 接続と切断のたびに、サーバー側にログを出す（相手のアドレスも表示する）

## 動作確認
ターミナルを 3 つ使う。

```
# ターミナル1
go run .

# ターミナル2, 3（それぞれ）
nc localhost 4242
```

`nc` で何か打って Enter → 同じ行が返ってくれば成功。`Ctrl-C` で切断。

---

## 作る順番

### ステップ1: 1 人だけ受け付けて、すぐ切る
- `net.Listen` で待ち受ける
- `Accept` で 1 接続だけ受け付ける → 相手のアドレスを表示 → 閉じる → 終了
- `nc` で接続して、サーバー側に表示が出れば OK

### ステップ2: 1 人とエコーする
- 接続から 1 行ずつ読み、そのまま書き返す
- 相手が切断したら、読むループを抜けて接続を閉じる

### ステップ3: 何人でも順番に受け付ける
- `Accept` をループにする
- `nc` を 2 つ同時に開くとどうなる？（2 人目は返事が来ない？）

### ステップ4: 同時に受け付ける
- 1 接続ごとに goroutine で処理する
- 2 つ同時に開いて、両方エコーされることを確認

## ヒント
- **パッケージ:** `net`（`Listen`、`Accept`、`Conn`）
- **`net.Conn` は `io.Reader` でもあり `io.Writer` でもある**
  - 読む: 課題 1〜3 で標準入力を読んだのと同じ方法が使える（`os.Stdin` の代わりに接続を渡す）
  - 書く: `fmt.Fprintln` や `fmt.Fprintf` の最初の引数に何を渡す？（課題 3 で stderr に書く話をした）
- **切断の検出:** 相手が切断すると、読む側はどうなる？（`Scan` が何を返すか）
- **後片付け:** 接続も Listener も `Close` が必要。`defer` で書き忘れを防ぐ
- **エラー処理:**
  - `Listen` の失敗（ポートが使用中など）→ 続けられない
  - `Accept` の失敗 → 1 回の失敗でサーバーごと止める？
  - 1 人のクライアントとの読み書きの失敗 → サーバーごと止める？
  - 課題 3 の後の「`log.Fatal` と `Println` の使い分け」を思い出す

## 考えてほしいこと
- `Listen` に渡すアドレスを `":4242"` と `"localhost:4242"` にした場合の違いは？（ほかの PC から接続できるか）
- 接続を処理する関数の中で `log.Fatal` するとどうなる？
- ステップ3で 2 人目が待たされるのはなぜ？課題 4 の何で解決できる？
- 1 人のクライアントが何も送らずに接続したままだと、ほかのクライアントに影響はある？（ステップ3 とステップ4 で比べる）
