# 06-chat ✅

TCP チャットサーバー。ある人の発言を、接続しているほかの全員に送る。

---

## 仕様
- ポート `4242` で待ち受ける（05 と同じ）
- 接続したら、最初に名前を聞く（`name? ` と送り、最初の 1 行を名前にする）
- 名前が決まったら、ほかの全員に `* <名前> が入室しました` と送る
- 発言すると、**自分以外の全員**に `[<名前>] <発言>` と送る
- 切断したら、残っている全員に `* <名前> が退室しました` と送る
- サーバー側にも、入室・退室をログに出す

### 余裕があれば
- `/who` と打つと、今いる人の名前一覧が自分にだけ返る
- `/quit` と打つと、自分の接続が切れる
- 名前が空、または既に使われていたら、もう一度聞く

## 動作確認
ターミナルを 3 つ以上使う（サーバー 1 + `nc` 2 つ以上）。

```
# ターミナル1
go run .

# ターミナル2, 3, ...
nc localhost 4242
```

**`go run -race .` で起動して、何人かで出入りと発言を繰り返しても警告が出ないこと。**

## ヒント

### 一覧をどう持つか
- 追加・削除が頻繁にある → slice と map のどちらが向いている？
- map のキーには何を使える？（`net.Conn` そのものをキーにできるか考える）
- 名前も一緒に持ちたくなったら？（値の型をどうする？）

### 一覧をどう守るか（2 つのやり方がある）
**やり方A: Mutex で守る**
- 一覧と `sync.Mutex` をまとめて 1 つの struct にする
- 一覧を触るところ（追加・削除・全員に送る）は全部 Lock する
- メソッドにしておくと、Lock の付け忘れを防げる

**やり方B: 一覧を触るのは 1 つの goroutine だけにする**
- 一覧を持つ専用の goroutine を 1 つ作り、ほかの goroutine は channel で「入室」「退室」「発言」を伝えるだけにする
- その goroutine は `select` で複数の channel を待つ（4c の応用）
- 一覧を触るのが 1 人だけなので Mutex がいらない

どちらでもよい。迷ったら A から。

### 考えてほしいこと

- 送信に失敗した相手はどう扱う？その場で一覧から消す？
- `handle` の中で一覧に追加・削除するとき、`defer` を使うと何がうれしい？
- やり方A と B、それぞれのいいところ・困るところは？
