# 04-concurrency

並行処理の練習。問題ごとにディレクトリを分ける（`a/` `b/` `c/`）。どれも `package main` なので同じディレクトリに置くと衝突する。

**共通:** 書き終わったら `go run -race .` でも実行し、警告が出ないことを確認する。

---

## 4a: 共有カウンタ ✅

### 仕様
- goroutine を 1000 個起動し、それぞれが共有の変数 `count` に 1 を足す
- 全部終わったら `count` を表示する（正しければ 1000）

### 進め方
1. わざと何も保護せずに書く → 何度か実行し、`-race` 付きでも実行して結果を見る
2. `sync.WaitGroup` だけ追加 → それでも 1000 未満になるなら原因はデータ競合
3. `sync.Mutex` を追加 → 毎回 1000、`-race` でも警告なし

### ヒント
- 全部の終了を待つ: `sync.WaitGroup`（`Add` / `Done` / `Wait`、または Go 1.25+ の `wg.Go`）
- 同時書き込みを防ぐ: `sync.Mutex`（`Lock` / `Unlock`、`defer` で Unlock する定番の書き方）
- `Add` は goroutine の**外**で呼ぶ（中だと `Wait` に先に着く可能性がある）

### 学んだこと
- `*a += 1` は「読む → 足す → 書く」の 3 段階 → 同時に実行すると加算が消える
- `time.Sleep` で待つのはだめ。`Wait` や channel は「終わった」だけでなく「書いた値が見える」ことも保証する（happens-before）
- `-race` の出力: `Read at ... by goroutine N` / `Previous write at ...` → 同じ場所への保護なしアクセス。行番号で守る場所が分かる

## 4b: ワーカープール ✅

### 仕様
- 1〜20 の数字を「仕事」として、ワーカー（goroutine）3 つに配る
- 各ワーカーは数字を受け取ったら少し待ち（`time.Sleep` で重い処理のつもり）、2 乗を結果として返す
- `main` は結果を全部受け取って合計を表示する
- どのワーカーが何を処理したかも表示する

### 作る順番
1. channel を 2 本作る（仕事を送る用、結果を受け取る用）
2. ワーカー関数を書く
   - 引数: ワーカー番号、仕事の channel、結果の channel
   - 仕事の channel から `for range` で受け取る → `time.Sleep` → 2 乗を結果の channel に送る
3. `main` でワーカーを 3 つ起動する
4. 1〜20 を仕事の channel に送る → 送り終わったら `close`
5. 結果を 20 個受け取って合計する → 表示

### ヒント
- channel の向きを型で書ける: `<-chan int`（受信専用）、`chan<- int`（送信専用）。間違った方向に使うとコンパイルエラーになる
- ワーカーの `for range` はいつ終わる？ → 仕事を送る側が最後にすることと関係がある（`close`）
- 結果を**ちょうど 20 個**受け取るなら、結果の channel は閉じなくても動く
- 結果を **`for range`** で受け取りたいなら閉じる必要がある
  - 閉じるのは「全部のワーカーが終わったとき」。それを知るには？（4a で使ったもの）
  - 閉じる処理を `main` に直接書くと、結果を受け取る前にそこで止まってしまう。どこに書く？
- バッファなし `make(chan int)` とバッファあり `make(chan int, 20)` で動きが変わる。送信（手順 4）と受信（手順 5）が同じ goroutine（`main`）にあり、バッファがないと何が起きる？

### 考えてほしいこと
- 結果の channel は、誰が・いつ閉じる？閉じるのが早すぎたり、閉じなかったりすると何が起きる？
- ワーカーを 3 つから 1 つにすると、かかる時間はどう変わる？（`time.Now` と `time.Since` で計る）

### 進め方
まず「ちょうど 20 個受け取る」版で動かす → 余裕があれば `close` して `range` で受け取る版

## 4c: タイムアウト ✅

### 仕様
- ランダムな時間（0〜2 秒）がかかる処理を goroutine で実行し、結果を channel で受け取る
- 1 秒以内に結果が来なければ `timeout` と表示する
- 何回か繰り返して、間に合う場合と間に合わない場合が両方出ることを確認する

### ヒント
- `select` と `time.After` を使う
- 乱数は `math/rand/v2`

### 考えてほしいこと
- タイムアウトしたとき、遅れていた goroutine は結果を送ろうとしたまま止まってしまう（goroutine リーク）。channel の作り方を少し変えると防げる（バッファ）
